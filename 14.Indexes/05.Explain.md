# Explain

- Generally, we write a query and get back the results. But we have no idea how `postgres` executed that query. Did it use full table scan or index scan. Did it used partitions efficiently or not.
- With explain we ask postgres about information on how our query is executed step by step.
- It does not execute the query just gives us the winning plan to execute a query. So, everything here is estimated not actual.


```sql
EXPLAIN your_statement
```

## Output format

- By default the output format of EXPLAIN is TEXT. But we can have it in JSON as well.

```sql
EXPLAIN (FORMAT JSON) statement
```

## Explain Analyze

- EXPLAIN shows what PostgreSQL plans to do.
- EXPLAIN ANALYZE Shows what actually happened when the query ran.
- Run the query and then give me insights about it rather than estinmating things.

```sql
EXPLAIN ANALYZE statement
```
