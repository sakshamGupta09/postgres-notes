# Index types

- Indexes are different “data structures” optimized for different kinds of queries.

## B-Tree 

- Best for
- Equality: `=`, Range queries: `<`, `>`, `BETWEEN`, `IN`, Sorting: ORDER BY
- This is used in ~90% of real-world cases.
- Drawback : It stores entire column value in the index so if a colun has large values size can grow rapidly.


🔹 Use case

- Find users with age = 25
- Find users with age > 30
- Sort users by age

## Hash Index

- Only equality: = or exact match
- No range queries, No sorting, Rarely better than B-Tree, In practice: almost never needed


## BRIN

- Instead of indexing every row, BRIN stores min and max value per block.
- It does NOT directly find rows, it first filters blocks and then filters inside teh blcok to select rows.
- BRIN index is very fast and space efficient for large data.
- Our data should be naturally ordered like logs or time series.

## GIN

- Perfect when a column contains multiple values.
- Best for
- Arrays
- JSONB
- Full-text search



## GiST

- Best for
- Geospatial data (Find nearby locations)
