# Index types

- Indexes are different “data structures” optimized for different kinds of queries.

## B-Tree 

- Best for
- Equality: `=`, Range queries: `<`, `>`, `BETWEEN`, `IN`, Sorting: ORDER BY.
- This is used in ~90% of real-world cases.
- Drawback : It stores entire column value in the index so if a column has large values size can grow rapidly.


🔹 Use case

- Find users with age = 25
- Find users with age > 30
- Sort users by age

## Hash Index

- Only equality: = or exact match
- No range queries, No sorting, Rarely better than B-Tree, In practice: almost never needed


## BRIN

- PostgreSQL stores tables as pages. If we have a table with 1 million rows it is stored in several pages of fixed size.

```sql
Table

Page 1  -> Rows 1–80
Page 2  -> Rows 81–160
Page 3  -> Rows 161–240
...
Page 10 -> Rows 721–800
```

## GIN

- Perfect when a column contains multiple values.
- Best for , Arrays, JSONB, Full-text search.



## GiST

- Best for
- Geospatial data (Find nearby locations)
