# Materialized views

- Till now, we were using views to store a query that used to run and return results whenever a view is accessed.
- Materialized views stores result of a query. Whenever we create or refresh materialized view, query runs and stores the result.
- Data is not always fresh but fetching is way faster.
- Performance vs Freshness


## Syntax

```sql
CREATE MATERIALIZED VIEW IF NOT EXISTS view_name AS QUERY
WITH [NO] DATA
```
- With data runs the query immediately and stores the result.
- No data creates an empty materialized view with no data. We need to manually refresh it before we can query it.

```sql
CREATE MATERIALIZED VIEW IF NOT EXISTS mv_directors AS
SELECT
	first_name,
	last_name
FROM directors
WITH DATA
```

## Insert/Update/Delete from materialized views

- We cannot perform INSERT, UPDATE or DELETE operation on materialized views.
- Because later if we refresh this, we are gonna loose that data.

## Refresh materialized view

- The query will be reexecuted and fresh results are stored physically.

```sql
REFRESH MATERIALIZED VIEW mv_name
```
