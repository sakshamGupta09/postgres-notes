# ACID Database

- It's a design pattern that every database tries to follow, be an ACID database.


## Atomicity (all or nothing)

- A transaction either fully succeeds or fully fails.
- Prevents half-done operations.
- If we are inserting a row, either full row is inserted with all columns or it's not inserted at all.


## Consistency (valid data only)

- Consistency means that a transaction takes the database from one valid state to another valid state.
- All defined rules—such as constraints, triggers, foreign keys, and checks—must still hold after the transaction completes.
- If a query breaks rules → transaction fails


## Isolation

- Each transaction works in its own bubble. Whatever changes we make in a transaction are not visible to others unless we COMMIT.
- Others can’t see your uncommitted changes.

## Durability (permanent after commit)

-  Once committed, data is safe even after crash.
-  Ensures no data loss after success.
